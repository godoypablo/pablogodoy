¿Qué es SIGEDO?

SIGEDO = Sistema Integrado de Gestión Electrónica de Documentos

Es un sistema web especializado para el Tribunal de Cuentas de Entre Ríos (TCER), una institución argentina que audita y controla las cuentas del gobierno provincial.

Propósito principal: Gestionar documentos financieros (rendiciones de cuentas, subsidios, multas), procesarlos a través de múltiples etapas de revisión y auditoría, firmarlos digitalmente y mantener un registro imutable de cada acción para auditoría permanente.

Estados de un Documento (Máquina de Estados)

Un documento pasa por estos estados en orden:

INGRESADO ↓ CARATULADO (se asigna auditor) ↓ EN_AUDITORÍA (auditor revisa) ↓ PENDIENTE_INFORME (se escribe informe) ↓ EN_REVISIÓN_SUPERIOR (jefe revisa) ↓ APROBADO (aprobación de superiores) ↓ PENDIENTE_CERTIFICACIÓN (listo para firmar) ↓ CERTIFICADO (firmado digitalmente) ↓ ARCHIVADO (guardado permanentemente)
💡 Importante: El sistema permite 100+ estados configurables. El admin puede agregar nuevos estados sin tocar código.

✓ Título no vacío
✓ Monto positivo
✓ Tipo válido

3. Se crea documento con estado INGRESADO

Problema Inicial:
⚠️ Si preguntas cada 100ms: "¿Hay firmas nuevas?"

= 36,000 requests por hora
= Servidor muy lento
= Base de datos saturada

Solución: ProcesoLento (Espera Inteligente)
Paso 1: Documento llega a PENDIENTE_CERTIFICACION Paso 2: Sistema espera 120 segundos Paso 3: (Una sola vez) Verifica: "¿Hay firmas pendientes?" Paso 4: Si NO → Espera otros 120 segundos Si SÍ → Notifica al jefe Paso 5: Jefe firma digitalmente Paso 6: Sistema registra firma: - Quién: Carlos García - Cuándo: 2024-07-08 14:30:15 - Con qué: Certificado Digital XYZ - Resultado: PDF oficial generado Paso 7: Estado → CERTIFICADO Paso 8: Organismo recibe notificación
✅ Resultado: 120 segundos × 8 horas = 240 requests/día (en lugar de 288,000)

Ejemplo: Jefe quiere ver "Estado por Auditor"

Lo que ve el Jefe:
Auditor | Asignados | En Auditoría | Completados | Demora Prom ─────────────────┼───────────┼──────────────┼─────────────┼──────────── Juan García | 15 | 8 | 5 | 5.3 días María López | 12 | 6 | 4 | 4.8 días Carlos Martínez | 10 | 5 | 3 | 6.2 días
SQL que corre detrás:
SELECT u.nombre, COUNT(d.id) AS documentos_asignados, COUNT(CASE WHEN d.estado = 'EN_AUDITORIA' THEN 1 END) AS en_auditoria, COUNT(CASE WHEN d.estado = 'CERTIFICADO' THEN 1 END) AS completados, ROUND(AVG(EXTRACT(DAY FROM NOW() - d.fecha_ingreso)), 1) AS demora_promedio FROM DOCUMENTO d JOIN USUARIO u ON d.auditor_id = u.id WHERE d.auditor_id IS NOT NULL GROUP BY u.id, u.nombre ORDER BY demora_promedio DESC

SERVICIO (Lógica - service-impl/) ServicioDocumento.crearDocumento(dto) → Valida reglas de negocio → Verifica permisos → Crea objeto Documento → Llama a DAO para guardar 4. DAO (Persistencia - dao-impl/) DocumentoDAO.save(documento) → Usa Hibernate → Convierte objeto Java → INSERT SQL 5. BASE DE DATOS (PostgreSQL) INSERT INTO DOCUMENTO (titulo, monto, estado, ...) VALUES ('Mi Documento', 50000, 'INGRESADO', ...) 6. RESPUESTA (vuelta) Documento guardado con ID = 12345 → Registra acción en ACTUACION → Notifica al usuario → Redirige a página de detalle

Ejemplo: Crear Documento

Código Java (Concepto):

@Service @Transactional public class ServicioDocumentoImpl { @Autowired private DocumentoDAO documentoDAO; public Documento crearDocumento(DocumentoDTO dto) { // Validación if (dto.getTitulo() == null) { throw new IllegalArgumentException("Título requerido"); } // Crear objeto Documento doc = new Documento(); doc.setTitulo(dto.getTitulo()); doc.setMonto(dto.getMonto()); doc.setEstado(TipoEstadoDocumento.INGRESADO); // Guardar documentoDAO.save(doc); // → INSERT en BD // Registrar en auditoría registrarAccion(doc, "Documento creado"); return doc; } }

Patrones Importantes

1. Separación de Capas

Web no habla con BD. Web → Servicios → DAOs → BD
Facilita testing, mantenimiento, reutilización

2. Transacciones (@Transactional)

Si algo falla → deshacer TODO
Evita datos inconsistentes

3. Inyección de Dependencias (@Autowired)

Spring crea objetos automáticamente
Facilita testing con mocks

4. Auditoría Imutable

CADA acción se registra en tabla ACTUACION
Quién, qué, cuándo, desde dónde
