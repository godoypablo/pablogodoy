Guía GitHub SIMPLE (Paso a Paso)

REGLA MÁS IMPORTANTE

SIEMPRE HACER ESTO ANTES DE TRABAJAR: 
git pull
SIEMPRE HACER ESTO AL TERMINAR: 
git add .
git commit -m "avance"
git push

PRIMERA VEZ (crear proyecto)

mkdir gastos-personales
cd gastos-personales
git init
git add .
git commit -m "inicio"
git remote add origin https://github.com/godoypablo/gastos-personales.git
git branch -M main
git push -u origin main

TRABAJAR TODOS LOS DÍAS

Paso 1 — Antes de trabajar

git pull

Paso 2 — Trabajar normalmente

Editar archivos

Paso 3 — Guardar cambios

git add .
git commit -m "avance"

Paso 4 — Subir a GitHub

git push

CAMBIAR DE PC

Primera vez en otra PC

git clone https://github.com/godoypablo/gastos-personales.git
cd gastos-personales

OTRO DÍA EN OTRA PC

SIEMPRE PRIMERO: 
git pull
Luego trabajar normalmente.

SUBIR AL SERVIDOR WEB

NUNCA copiar archivos manualmente. En el servidor hacer: 
git pull

FLUJO PERFECTO

Mañana

git pull

Trabajar

Editar archivos

Guardar

git add .
git commit -m "avance"

Subir

git push

SI ALGO FALLA

Ejecutar: 
git status
Debe decir:
En la rama main
Tu rama está actualizada con 'origin/main'

VOLVER ATRÁS A UNA VERSIÓN QUE FUNCIONABA

Paso 1 — Ver versiones anteriores

git log --oneline
Ejemplo: 
a34f2d1 cambio nuevo que rompió todo
b91ac22 versión que funcionaba bien
7aa9910 inicio del proyecto

Paso 2 — Copiar el código de la versión que funcionaba

b91ac22

Paso 3 — Volver a esa versión

git reset --hard b91ac22

Paso 4 — Subir esa versión a GitHub

git push --force
Esto deja el proyecto exactamente como estaba antes

VOLVER ATRÁS SOLO UN PASO

git reset --hard HEAD~1
git push --force

VOLVER ATRÁS DE FORMA SEGURA

git revert HEAD
git push

RESUMEN VOLVER ATRÁS

git log --oneline
git reset --hard CODIGO
git push --force

RESUMEN GENERAL

ANTES → git pull
TRABAJAR
DESPUÉS → git push

git log
